# シナリオメーカー マニュアル

このマニュアルは、`prototype/scenario-maker/` にあるシナリオメーカー試作版の使い方を説明します。人物、証拠品、ログ、判明事項などを編集し、事件データをJSONファイルとして保存できます。

このメーカーは、[`data-design.md`](data-design.md)で定めた`schemaVersion: 1`の事件データを編集します。

事件既定・人物・証拠品・ログ・会話グラフ・会話ノードに背景を、人物・証拠品・会話ノードにアイコンを設定できます。設定がない場合は上位の既定画像を使います。会話は人物ごとに複数作成でき、人物の`interactions[]`内で編集します。進行状況による会話の変化は、会話グラフの表示条件やグラフ内の条件付き分岐で作ります。

## 起動方法

プロジェクトのルートで次のコマンドを実行し、ブラウザで `http://localhost:3000/scenario-maker/` を開きます。

```powershell
node prototype/server.mjs
```

サーバーを起動せずに `index.html` を直接開く方法もありますが、既存の事件データをURLから読み込む機能など一部の動作は使えません。

## 画面の構成

- **事件情報（左上）**: 事件ID、事件名、種類別の共通背景を設定します。
- **編集する項目（左側）**: 人物や証拠品などの種類を切り替え、項目の追加・選択をします。
- **項目一覧（中央）**: 選択中の項目と会話ノードなどの構成を表示します。
- **項目編集（右側）**: 選択中の項目の値を編集し、下部で検証結果を確認します。
- **JSON全体表示**: 上部のボタンから、現在の事件データ全体を確認・コピーできます。

左・中央・右の境界をドラッグすると幅を調整できます。境界を選択して左右キーを押しても変更でき、幅はこのブラウザに保存されます。画面が狭い場合は縦並びになり、境界操作は無効になります。

## 新しい事件を作る

1. 事件IDと事件名を入力します。IDは英数字とアンダースコアなどを使った、他の事件と重ならない値にします（例：`case002`）。
2. 左側の項目種別を選び、＋ボタンで項目を追加します。
3. 中央の編集欄にID、表示名、説明などを入力します。
4. 必要な項目を追加し、データ検証の結果を確認します。
5. **JSONを書き出す**を押し、ダウンロードしたファイルを保存します。

追加した項目には仮のIDと空欄が入ります。各項目に固有のIDと必要な表示名を設定してください。IDはデータ間の参照に使うため、同じ事件内で重複させないでください。

## 項目種別

| 種別 | 主な内容 |
| --- | --- |
| 人物 | ID、表示名、役割、アイコン、選択画面の背景、表示条件、複数の会話グラフ |
| 証拠品 | ID、表示名、アイコン、選択画面の背景、説明、調査項目 |
| ログ | ID、表示名、説明、ログ行 |
| 判明事項 | ID、表示名、説明、表示順 |
| Event | ID、起動元の種類と対象、Effect |
| ヒント | ID、対象ID、段階定義 |

人物を選択し、中央の**会話を追加**から会話グラフを作ります。人物に複数の会話を割り当てられます。進行状況ごとに異なる入口を作る場合は、各会話の表示条件を設定します。会話内の細かな分岐は、ノード・条件付き選択肢・条件付き自動分岐で作ります。ノード、選択肢、証拠調査、ログ行、ヒント段階にはEventを選択して関連付けられます。Event側でも起動元を選ぶと、その起動元へEventが関連付けられます。Effectの種類と対象も選択式です。JSONを直接入力する欄は事件共通設定だけです。会話文・説明文・選択肢・ログ行は複数行入力に対応しています。

具体的なフィールド構造やCondition / Effectの仕様は [`data-design.md`](data-design.md) と [`game-engine.md`](game-engine.md) を参照してください。

## 既存のJSONを編集する

1. **JSONを読み込む**を押します。
2. 編集する `.json` ファイルを選択します。
3. 左側で編集したい項目を選び、内容を変更します。
4. 検証結果を確認して、JSONを書き出します。

読み込みに成功すると、画面上の現在のデータが読み込んだデータに置き換わります。必要な配列がファイルにない場合、メーカーは空の配列として扱います。読み込む前に、必要なら元ファイルのコピーを保管してください。

## 保存・書き出し・コピー

- 編集内容はブラウザのローカルストレージに自動保存されます。同じブラウザで次回開いたときに下書きが復元されます。
- 自動保存はJSONファイルの書き出しではありません。成果物を残すには**JSONを書き出す**を使ってください。
- **コピー**はプレビュー中のJSON全体をクリップボードにコピーします。
- 書き出し時に検証エラーがあるとダウンロードできません。表示されたエラーを修正してから再度書き出してください。

同じブラウザの下書きが読み込んだファイルより優先されるため、別ファイルから作業を始める場合は、先にそのファイルを**JSONを読み込む**で選択してください。

## データ検証

現在の検証機能は主に次の項目を確認します。

- 事件ID・事件名が入力されているか
- 各項目がオブジェクトで、IDを持っているか
- 項目IDが重複していないか
- Event以外の項目に表示名があるか
- 会話グラフの開始ノードとノード遷移先が存在するか
- Event起動元が存在し、起動元側のEvent参照と一致しているか
- 条件分岐専用ノードに本文や通常遷移が混在していないか

検証はシナリオ全体の正しさやゲーム上の進行可能性を保証するものではありません。Conditionの参照先、会話ノードの接続、Effectの意味などは設計資料と照らして確認してください。

## 現行試作の制限

- 全種別を1つのJSONファイルとして読み書きします。種別ごとのファイル分割には対応していません。
- 旧形式の最上位`conversations[]`は、各会話の最初の非`player`・非`narrator`話者を担当人物として`interactions[]`へ移します。人物内`interaction`形式も、一件の会話として読み込みます。
- 現在のメーカーは試作版です。検証表示はシナリオの全ての意味的な誤りや進行不能を検出するものではありません。
- ダウンロードしたJSONを `prototype/case001.json` に置き換えると、現在の試作ゲームで読み込めます。元データを残したい場合は、置き換える前にバックアップを作成してください。

## 項目の削除

項目を選択し、中央上部の**この項目を削除**を押すと、選択中の項目が事件データから削除されます。参照元のIDは自動では修正されないため、削除後はデータ検証を実行し、関連する参照も確認してください。
