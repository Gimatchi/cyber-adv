# 事件002「SNS乗っ取り」シナリオ骨組み（案）

## この文書の位置づけ

Case 002の物語草稿と捜査ルートをゲームデータへ分解するための骨組み案。Case 001の人物・事件設定・JSONを変更しない。Case 001のシナリオデータは作成途中のため、完成形の見本とはせず、確定済みの共通データ形式と再利用できる表現だけを参考にする。以前作成したAI生成のJSON初稿は`prototype/scenarios/case002-yobi.json`に参考用として保管し、新しいCase 002 JSONは人力で作り直す。

本番では運営側が有効なシナリオを指定し、参加者はシナリオを選ばない。Case 001とCase 002を両方実装する場合も、参加者用の選択画面は設けない。詳細は[`game-design.md`](game-design.md)の「Case 002の追加方針」を参照。

## 1. 事件の軸

地下アイドルとして活動する土崎彩花のSNSアカウントが不正に利用され、本人らしくない投稿が行われる。投稿は彩花の活動上の信用を傷つけるとともに、彼氏との信頼関係を壊そうとするもの。犯人の天童拓海は、ライブや握手会に通うファンとして彩花を一方的に知り、公開情報や活動中の様子から彼氏の存在を知る。二人の私的な接点は設定しない。

捜査の中心は端末、メール、SNSログ、ホスティング記録、通信事業者記録。ライブ会場・握手会会場での聞き込みや運営者照会は必須にしない。

## 2. 基本進行案

| 段階 | 捜査内容 | 得られる情報・次の段階 |
|---|---|---|
| 1. 被害相談 | 彩花からアカウントへの不正利用、投稿被害、待ち伏せを示す投稿画像を確認 | 画像証拠を取得。スマートフォン等の本格調査はまだ行わない |
| 2. 待ち伏せ画像OSINT | Case 001完成版の調査グラフを流用し、目視、Exif、座標照合を行う | 「待ち伏せ場所は大手交番」のFact。これを得るまで端末・ログ調査をロック |
| 3. 彩花の端末 | 不審メール、偽ログイン画面、閲覧履歴、入力時刻を確認 | メール・サイト・SNS記録の照合へ |
| 4. SNSログ | 不審なログインと投稿の時刻、接続情報を確認 | 単独のIPで人物を特定せず、メール・事業者記録を追う |
| 5. 公開情報の確認（任意） | 公開投稿や活動情報から、彼氏の存在や情報の公開範囲を確認 | 動機・情報入手可能性の補助。人物特定には使わない |
| 6. Mailia照会 | メール送信元に関する記録を確認 | フィッシングサイトとの関連を追う |
| 7. NexHost照会 | フィッシングサイトの運用・アクセス記録を確認 | アクセス元と時刻を得る |
| 8. BrightNet照会 | 該当時刻の回線契約情報を照会 | 天童を捜査対象として浮上させる。契約者情報だけで断定しない |
| 9. 捜索の相談・実施 | 複数記録を整理し、目的・対象・根拠を確認 | 適切な手続を経て端末等を取得する流れへ |
| 10. 天童の端末解析 | サイト閲覧・メール送信・認証情報・投稿計画等を確認 | 独立した記録を結び付け、動機と犯行を裏付ける |
| 11. 最終追及 | 端末・事業者・SNSの記録を示して確認 | 供述を得て事件をクリア |

### 章構成案

全5章（第0章～第4章）とする。章の切替は、表に示す捜査結果がEventまたはFactとしてPlayerStateに記録された時点で行う。画面には現在の章だけを表示し、未到達の章名は表示しない。章と進捗ゲージの共通仕様は[`game-design.md`](game-design.md)を参照する。

| 章 | プレイヤーに表示する目的 | 章を終えて次へ進む目安 |
|---|---|---|
| 第0章 | 相談者から聴取せよ | 彩花への初回聞き込みが完了し、待ち伏せ投稿画像などの捜査資料を得る |
| 第1章 | 待ち伏せ場所を特定せよ | 画像の目視・Exif・座標照合を行い、撮影場所のFactを得る |
| 第2章 | アカウントを奪った手口を追え | 彩花の端末、Chirpログ、メールヘッダーを調べ、Mailiaの回答からフィッシングサイトの運営元を把握する |
| 第3章 | 接続記録から捜査対象を絞れ | NexHostとBrightNetの回答を照合し、接続元の契約者情報を得る。契約者情報だけで犯人と断定しない |
| 第4章 | 端末の証拠を固めて追及せよ | 適切な手続で取得した端末の記録を調べ、他の資料と照合した上で追及し、自白によりクリアする |

第2章は乗っ取りの手口と使われた環境を明らかにする段階、第3章は事業者の接続記録から捜査対象を絞る段階とする。公開情報や友人との任意会話は主進行の必須条件にせず、章の進行度にも加算しない。

## 3. 人物会話の役割案

- **土崎彩花:** 被害の申告、メール・投稿・アカウントの状況説明。天童との接点はライブと握手会でのファン対応に限る。
- **天童拓海:** 彩花の活動を追うファン。公開情報などを通じて彼氏の存在を知り、二人の関係を壊す目的でアカウントを不正利用した。
- **雛泉理子:** 彩花の友人。一般論としてファンとの距離感に注意するよう伝えていた。天童との面識はなく、犯人特定の直接証拠を持たない。任意会話とする。
- **彩花の彼氏:** 被害の影響と動機の背景を示す人物。名前・詳細・ゲーム内での登場方法は未確定。犯人特定の手掛かりを与える必須捜査対象にはしない。
- **捜査員・上司:** 記録の限界、適切な照会、複数記録の照合、捜索の目的と根拠を補足する。

## 4. 設計上の制約

- 公開情報や雛泉の発言のみで天童を犯人と特定しない。
- 単一のIPアドレス、契約者情報、供述のみで犯人と断定しない。
- ライブ・握手会会場に行かなくても事件を解決できる。
- 待ち伏せ画像OSINTは必須の導入捜査としてCase 001完成版の調査グラフを流用する。公開情報の確認はこれと別の任意補助要素とする。
- 画像のExif座標は撮影場所の手掛かりであり、投稿者や実際の待ち伏せを単独で証明するものではない。
- 事件固有の進行は会話、Condition、Event、Effect等のシナリオデータで表現する。Case 002専用のエンジン処理は追加しない。
- 共通画像・音声素材はCase 001と共有する。Case 002固有の素材を追加する場合も共通素材領域へ配置する。

## 5. JSON化前の未確定事項

- 乗っ取り後の投稿の具体的な文面・画像・被害範囲。
- 画像原本をどのようにプレイヤーへ提示し、架空地図上の「大手交番」と座標を照合させるか。
- 彩花の彼氏を会話可能人物として出すか、彩花の説明・資料だけで扱うか。
- Mailia、NexHost、BrightNet各社の回答内容と、記録を結ぶ時系列・照会根拠。
- 捜索対象、取得資料、手続説明のゲーム上の具体化。
- 天童の端末に残る犯行裏付け資料と、各資料が補強する事実。
