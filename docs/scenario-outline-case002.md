# 事件002「SNS乗っ取り」シナリオ骨組み（案）

## この文書の位置づけ

Case 002の物語草稿と捜査ルートをゲームデータへ分解するための骨組み案。Case 001の人物・事件設定・JSONを変更しない。Case 001のシナリオデータは作成途中のため、完成形の見本とはせず、確定済みの共通データ形式と再利用できる表現だけを参考にする。試作JSONは作成済みだが、下記の未確定事項を含む初稿である。

本番では運営側が有効なシナリオを指定し、参加者はシナリオを選ばない。Case 001とCase 002を両方実装する場合も、参加者用の選択画面は設けない。詳細は[`game-design.md`](game-design.md)の「Case 002の追加方針」を参照。

## 1. 事件の軸

地下アイドルとして活動する土崎彩花のSNSアカウントが不正に利用され、本人らしくない投稿が行われる。投稿は彩花の活動上の信用を傷つけるとともに、彼氏との信頼関係を壊そうとするもの。犯人の天童拓海は、ライブや握手会に通うファンとして彩花を一方的に知り、公開情報や活動中の様子から彼氏の存在を知る。二人の私的な接点は設定しない。

捜査の中心は端末、メール、SNSログ、ホスティング記録、通信事業者記録。ライブ会場・握手会会場での聞き込みや運営者照会は必須にしない。

## 2. 基本進行案

| 段階 | 捜査内容 | 得られる情報・次の段階 |
|---|---|---|
| 1. 被害相談 | 彩花からアカウントへの不正利用と投稿被害を聞く | スマートフォン等の確認に進む |
| 2. 彩花の端末 | 不審メール、偽ログイン画面、閲覧履歴、入力時刻を確認 | メール・サイト・SNS記録の照合へ |
| 3. SNSログ | 不審なログインと投稿の時刻、接続情報を確認 | 単独のIPで人物を特定せず、メール・事業者記録を追う |
| 4. 公開情報の確認（任意案） | 公開投稿や活動情報から、彼氏の存在や情報の公開範囲を確認 | 動機・情報入手可能性の補助。人物特定には使わない |
| 5. Mailia照会 | メール送信元に関する記録を確認 | フィッシングサイトとの関連を追う |
| 6. NexHost照会 | フィッシングサイトの運用・アクセス記録を確認 | アクセス元と時刻を得る |
| 7. BrightNet照会 | 該当時刻の回線契約情報を照会 | 天童を捜査対象として浮上させる。契約者情報だけで断定しない |
| 8. 捜索の相談・実施 | 複数記録を整理し、目的・対象・根拠を確認 | 適切な手続を経て端末等を取得する流れへ |
| 9. 天童の端末解析 | サイト閲覧・メール送信・認証情報・投稿計画等を確認 | 独立した記録を結び付け、動機と犯行を裏付ける |
| 10. 最終追及 | 端末・事業者・SNSの記録を示して確認 | 供述を得て事件をクリア |

## 3. 人物会話の役割案

- **土崎彩花:** 被害の申告、メール・投稿・アカウントの状況説明。天童との接点はライブと握手会でのファン対応に限る。
- **天童拓海:** 彩花の活動を追うファン。公開情報などを通じて彼氏の存在を知り、二人の関係を壊す目的でアカウントを不正利用した。
- **雛泉理子:** 彩花の友人。一般論としてファンとの距離感に注意するよう伝えていた。天童との面識はなく、犯人特定の直接証拠を持たない。任意会話とする。
- **彩花の彼氏:** 被害の影響と動機の背景を示す人物。名前・詳細・ゲーム内での登場方法は未確定。犯人特定の手掛かりを与える必須捜査対象にはしない。
- **捜査員・上司:** 記録の限界、適切な照会、複数記録の照合、捜索の目的と根拠を補足する。

## 4. 設計上の制約

- 公開情報や雛泉の発言のみで天童を犯人と特定しない。
- 単一のIPアドレス、契約者情報、供述のみで犯人と断定しない。
- ライブ・握手会会場に行かなくても事件を解決できる。
- OSINTを入れる場合は、公開情報から分かる範囲と限界を区別し、補助情報として扱う。
- 事件固有の進行は会話、Condition、Event、Effect等のシナリオデータで表現する。Case 002専用のエンジン処理は追加しない。
- 共通画像・音声素材はCase 001と共有する。Case 002固有の素材を追加する場合も共通素材領域へ配置する。

## 5. JSON化前の未確定事項

- 乗っ取り後の投稿の具体的な文面・画像・被害範囲。
- OSINTをゲームの必須進行に含めるか、任意の補助情報にするか。
- 彩花の彼氏を会話可能人物として出すか、彩花の説明・資料だけで扱うか。
- Mailia、NexHost、BrightNet各社の回答内容と、記録を結ぶ時系列・照会根拠。
- 捜索対象、取得資料、手続説明のゲーム上の具体化。
- 天童の端末に残る犯行裏付け資料と、各資料が補強する事実。

現行の試作JSONは[`prototype/scenarios/case002.json`](../prototype/scenarios/case002.json)。上記の未確定事項は物語草稿・設計書と照合して決め、JSONを更新する。現行JSONは完成・本番用データではない。
