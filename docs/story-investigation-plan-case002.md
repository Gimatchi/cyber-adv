# 事件002 ストーリー・捜査方針

**位置づけ:** Case 001の設計書・シナリオデータを変更せず、新規作成するCase 002の物語・捜査設計を定める方針書。  
**作成日:** 2026-10-17（元方針案: 2026-10-15）

## 1. 目的

事件002の人物関係と犯行動機を、地下アイドルへのストーカー行為を背景とする新規シナリオとして設定する。捜査の主軸は端末・SNS・メール・事業者記録などの証拠分析とする。ライブや握手会の現場捜査は行わない。

この文書はCase 002の制作指針であり、Case 001の既存仕様を上書きしない。必要な設計書とシナリオデータはCase 002用に追加する。

## 2. 固定する人物設定

- 被害者の正しい名前は**土崎彩花（つちざき あやか）**。「土崎綾香」は誤字として扱う。
- 彩花は地下アイドルとして活動している。
- 天童拓海は彩花のファンで、握手会だけでなくライブにも継続して参加していた。
- 天童と彩花の接点は、アイドル活動中の握手会・ライブに限る。大学、職場、共通の友人など、私的なつながりは持たせない。
- 天童はライブや公開情報を通じて彩花に彼氏がいると知り、二人を別れさせたいと考える。
- 天童は彩花のSNSアカウントを不正に利用し、本人らしくない投稿を行う。彩花を困らせると同時に、彼氏との信頼関係を壊すことが狙い。
- 雛泉理子は彩花の友人。天童との面識・接点はない。一般論として、距離感を誤るファンやストーカーまがいのファンに注意するよう彩花へ伝えていた。
- 雛泉の発言は彩花の不安や当時の状況を示すものであり、天童の犯行を知っていたことや、天童を特定する直接証拠にはしない。

## 3. 犯行動機と経緯の整理

改訂時は、次の因果関係がプレイヤーに伝わるようにする。

1. 天童はライブや握手会に通う中で、彩花を一方的に知る。
2. 彩花の公開情報や活動中の様子から、彼氏の存在を知る。
3. 天童は彼氏への嫉妬と、彩花との関係を自分の思い通りにしたいという執着を募らせる。
4. アカウントを不正に利用し、彩花本人が投稿したように見える内容を公開する。
5. 投稿によって彩花の活動や評判を傷つけ、彼氏との関係にも亀裂を生じさせようとする。

「困らせる」と「別れさせる」は別々の動機として並べず、**関係を壊すための投稿が、彩花を困らせる犯行でもある**と整理する。投稿の具体的内容は、被害の現実味と作品の表現方針に合わせてシナリオ作成時に定める。

## 4. 捜査の方針

### 主軸として維持するもの

- 彩花からの聞き取りと、アカウント乗っ取り・投稿による被害の確認
- スマートフォン、メール、SNSログなどの確認
- メール・ホスティング・通信事業者への適切な照会
- 照会記録、アクセス記録、端末内の記録を組み合わせた天童の特定
- 天童の端末など、犯行を裏付ける証拠の確認と追及

契約者情報や一つのIPアドレスだけで犯人と断定しない。既存方針どおり、複数の独立した記録を組み合わせて判断する。

### ライブ・握手会の扱い

ライブや握手会は、天童が彩花を知り、彼氏の存在を知るに至った背景として扱う。イベント会場での聞き込み、参加者の追跡、イベント運営者への照会を捜査ルートの必須要素にはしない。会場で得た情報を犯人特定の決め手にもしない。

### OSINTの追加案

OSINTを加える場合は、彩花の公開投稿や公開された活動情報を資料として扱い、動機・情報の入手可能性・投稿の時系列を理解する補助にする。たとえば、公開投稿から交際相手の存在が推測できることや、活動予定が公表されていたことを確認する。

OSINTだけで天童個人を特定したり、公開投稿を根拠にストーカー行為を断定したりしない。個人の住所などの特定をゲームの課題にせず、公開情報の限界と、ログや事業者記録で裏付ける必要性も示す。

## 5. 現行構成からの主な見直し候補

元のCase 001案に含まれていた要素のうち、Case 002では次のように扱う。

- 天童と黒見の知人関係、黒見経由の情報取得はCase 002に引き継がない。
- 雛泉は一般的な注意喚起をしていた友人とし、天童の好意・接近を直接知る立場にしない。
- 彩花の被害と、彼氏との信頼関係を壊そうとする投稿内容をCase 002用に定義する。
- 待ち伏せ場所画像OSINTは引き継がず、公開投稿・活動情報のOSINTを補助的に使うかを決める。
- OSINTを使う場合も、イベント現場の捜査を必須にせず、端末・ログ中心のルートと接続する。
- 会話、証拠、Fact、Condition、Event、時系列、クリア条件をCase 002の動機と証拠の流れに合わせて作成する。
- Case 002の人物設定、シナリオ概要、草稿、設計資料を新規作成・追記する。Case 001の既存データは変更しない。

## 6. エンジンとデータ設計への影響

この変更は事件002の人物・証拠・会話・Fact・進行条件の変更として表現する。事件固有の処理をゲームエンジンへ追加しない。既存のState / Condition / Effect / Event、ログ調査、サーバー側での進行検証を基本的に維持する。

新しいOSINTの段階が必要になった場合も、既存の会話グラフ、選択肢、Condition、Eventで表現できるかを先に確認する。既存データ形式で表現できない要求が見つかった場合は、実装を始める前にデータ設計への影響を検討する。

## 7. 改訂時の確認項目

- 彩花の名前が「土崎彩花」に統一され、「土崎綾香」が残っていない。
- 天童の彩花との接点がライブ・握手会の範囲に収まっている。
- 天童が彼氏の存在を知る経路と、不正アクセス・投稿の動機が説明されている。
- 雛泉は天童と無関係で、一般的な注意喚起の範囲に留まっている。
- ライブや握手会へ行かなくても、ログ・端末・事業者記録を分析して事件を解決できる。
- OSINTを使う場合、公開情報から言えることと言えないことが区別され、単独で犯人を断定しない。
- 事件固有の変更がシナリオデータに収まり、エンジンに専用分岐が増えていない。
